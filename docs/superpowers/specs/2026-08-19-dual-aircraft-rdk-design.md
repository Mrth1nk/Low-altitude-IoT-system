# 双飞机 RDK 节点扩展设计

日期：2026-08-19
状态：已确认，等待实施计划

## 1. 目标

在不破坏当前小车、ELF 主机、L610 和涂鸦云稳定链路的前提下，新增一架搭载 RDK-X5 的从机。小车 RDK 作为唯一云网关和任务调度器，通过 `woshinailong` 局域网直接与从机 RDK 双向通信，并将小车、主机和从机状态统一上报涂鸦。

地面站新增从机任务界面。从机支持与主机一致的模式、解锁和航点任务指令。主机和从机必须具有独立状态、独立消息历史、独立命令事务和独立故障判定。

## 2. 已验证的设备条件

- `woshinailong` 支持小车 RDK 与从机 RDK 同时接入。
- 小车 RDK 使用 `192.168.4.2`，从机测试地址为 `192.168.4.3`。
- 两节点实测 100 次 UDP 请求和 ACK 全部成功，零丢包、零重复、零串包。
- 实测平均 RTT 为 5.75 ms，P95 为 19.74 ms，最大为 47.32 ms。
- 数传热点未启用客户端隔离，从机可以直接 SSH 和 UDP 访问小车。
- 从机 RDK 已安装 `pymavlink 2.4.48`。
- 从机飞控为 ArduPilot Copter，两个固定 `by-id` 接口均能读到真实 `HEARTBEAT`，当前模式为 `STABILIZE`。
- 从机当前没有其他 MAVLink 服务占用飞控串口。

当前配置下，从机发送到数传模块 `192.168.4.1:14555` 的探针未在 ELF 串口计数中出现。因此本设计不要求从机争用 ELF 的串口透明通道，而使用已经实测通过的从机 RDK 到小车 RDK 直接 UDP 链路。

## 3. 系统架构

```text
本机地面站
    |
    | Tuya OpenAPI
    v
涂鸦云
    |
    | TuyaLink / L610
    v
小车 RDK 192.168.4.2
    |-- USB MAVLink --> 小车 Rover 飞控
    |-- 现有数传链路 --> ELF 主机 --> 主机 Copter 飞控
    `-- 节点 UDP ------> 从机 RDK 192.168.4.3 --> 从机 Copter 飞控
```

### 3.1 节点身份

系统使用稳定节点 ID：

- `rover`：小车 RDK 和小车飞控。
- `aircraft_1`：现有 ELF 主机和主机飞控。
- `aircraft_2`：新增从机 RDK 和从机飞控。

所有跨节点消息必须携带 `source`、`target`、`command_id`、`sequence` 和消息时间。接收端只处理目标为本节点的消息。

### 3.2 地址与端口

- 小车 RDK：`192.168.4.2`。
- 从机 RDK：`192.168.4.3`。
- 小车节点协议监听：UDP `14610`。
- 从机节点协议监听：UDP `14620`。

端口与现有主机链路的 `14550/14555/14560` 分离，避免影响已经成功的 ELF 通道。

## 4. 从机服务

从机运行一个新的单进程服务，职责包括：

1. 独占一个固定飞控 `by-id` 接口。
2. 持续读取真实飞控 MAVLink 心跳和状态。
3. 每秒向小车发送一次紧凑状态。
4. 接收小车发来的从机命令并写入有界队列。
5. 在本地按顺序与飞控完成模式、解锁和任务握手。
6. 将 ACK、事务阶段、任务结果和故障回传小车。
7. 将状态和任务日志原子写入本地运行目录，便于重启恢复和排障。

从机支持以下控制：

- `GUIDED`
- `LOITER`
- `AUTO`
- `LAND`
- `ARM`
- `DISARM`
- 完整航点任务上传

从机复用现有主机经过验证的 `MavlinkSession`、命令执行和任务握手逻辑，不重新手写第二套 MAVLink 协议。

### 4.1 串口所有权

从机服务是指定 MAVLink `by-id` 接口的唯一读取者。状态采集、命令确认和任务握手通过同一个会话分发，禁止多个进程同时 `recv_match()`，避免 ACK 被错误进程消费。

安装前检查必须验证：

- `by-id` 唯一存在并解析到预期设备。
- 串口未被其他进程占用。
- 收到 Copter 类型的飞控心跳。
- 飞控 `SYSID_THISMAV` 与主机不同；建议主机为 1，从机为 2。参数修改前必须备份，并输出恢复命令。

## 5. 节点协议与事务

节点网络传输采用带边界、校验和类型验证的现有 LIOT 思路，不在局域网广播原始 MAVLink。

### 5.1 状态消息

状态至少包含：

- 节点 ID 和状态序号。
- 更新时间和飞控心跳时间。
- 模式、解锁状态和飞控连接状态。
- 经纬度、位置是否真实观测、高度、速度、航向。
- 电量展示值。
- 当前任务阶段、任务 ID 和故障。
- 链路状态和预留光路状态。
- 最新一条带原始时间戳和序号的消息。

### 5.2 命令事务

每条命令使用 UUID 作为 `command_id`。从机按如下阶段处理：

```text
RECEIVED -> QUEUED -> EXECUTING -> VERIFIED
                              `-> FAILED
```

- 小车未收到 ACK 时按固定间隔有限重试。
- 从机按 `command_id` 去重，重复包返回原事务状态，不重复执行。
- 过期命令、队列满、目标错误和格式错误必须明确 NACK。
- 简单命令只有在真实飞控心跳确认模式或解锁状态后才报告 `VERIFIED`。
- 阻塞任务不得占用 UDP 接收循环；网络接收、任务队列和 MAVLink 执行分离。

### 5.3 航点任务

航点采用先完整接收、再本地写入飞控的策略：

1. 小车发送任务开始、所有航点和任务提交帧。
2. 从机按任务 ID、数量和 SHA-256 校验任务完整性。
3. 完整任务先持久化到本地收件箱。
4. 独立任务工作线程按照 ArduPilot `MISSION_COUNT`、`MISSION_REQUEST_INT`、`MISSION_ITEM_INT`、`MISSION_ACK` 流程写入。
5. 任务写入后读取任务数量或确认 ACK，成功后才允许切换 `AUTO`。
6. 任务失败保留旧任务，不执行半包任务。

## 6. BLOCKED 预留接口

从机第一版不启用视觉 `BLOCKED` 判定：

- 默认 `optical.blocked=false`。
- 不继承主机 ELF 的光路状态。
- UDP 状态超过 3 秒未更新时显示 `OFFLINE`，并拒绝新的从机指令。
- `OFFLINE` 与 `OPTICAL BLOCKED` 是两个不同状态。

从机服务仍定义独立 `OpticalGate` 接口和状态字段。后续安装红外摄像头时，只需替换 gate 数据源，不修改节点协议、涂鸦字段和地面站控制逻辑。

未来启用视觉 gate 后：

- `blocked=true` 时拒绝新的云端控制与航点任务。
- 本地飞控、遥控器和安全模式继续工作。
- 地面站在从机页签和消息区显示带时间的 `OPTICAL LINK BLOCKED`。

## 7. 小车调度器

小车保留现有主机链路，并新增独立从机链路对象：

- 主机与从机使用不同 peer、端口、状态文件和事务对象。
- 从机掉线不得改变主机状态或清空主机消息。
- 主机命令阻塞不得阻塞从机 UDP 接收。
- 从机命令失败不得覆盖小车或主机任务结果。
- 调度器根据 `target` 路由到 `rover`、`aircraft_1` 或 `aircraft_2`。

现有客户端发送的 `target=aircraft` 在兼容层中继续映射为 `aircraft_1`，避免旧地面站和旧任务失效。

## 8. 涂鸦状态与字节限制

### 8.1 属性拆分

- `rover_state`：保持当前格式和优先级，继续承载小车与主机状态。
- `slave_state`：新增字符串属性，仅承载 `aircraft_2` 状态。

小车每两秒发送一次 TuyaLink property report，并在同一 report 的 `data` 中同时包含两个属性。因此：

- 设备上报频率不增加。
- 地面站 OpenAPI 轮询次数不增加。
- 一次影子或状态读取即可得到两个属性。
- 两个属性分别遵守 480 字节上限，互不挤占。

### 8.2 从机压缩状态

`slave_state` 必须通过专用压缩器生成，并在测试中断言 UTF-8 长度不超过 480 字节。优先级如下：

1. 更新时间、在线状态、模式和解锁状态。
2. 真实位置、高度、速度和航向。
3. 任务阶段和命令结果。
4. 最新消息的时间、类型、序号和截断文本。
5. 非关键诊断字段。

地面站在本机累计消息历史，云端每次只需要保存最新消息。部分属性读取缺失时，地面站保留上一份有效主机或从机详情，但根据各自时间戳显示是否过期。

### 8.3 命令属性

第一版复用现有命令属性，不为每个从机按钮创建新的 DP。地面站通过：

```json
{
  "command": "aircraft_guided",
  "target": "aircraft_2",
  "command_id": "UUID",
  "source_timestamp": 1780000000.0
}
```

区分主机和从机。如果涂鸦 `target` 当前为枚举，则在产品功能定义中增加 `aircraft_2`；如果为字符串，则无需修改类型。

## 9. 地面站界面

采用已确认的 A 方案。

### 9.1 地图任务选择

地图任务分段控制由两个选项扩展为：

- 小车
- 主机
- 从机

三类任务分别维护航点队列、路线、编号、颜色和上传目标。从机航点与主机一样显示统一高度输入，并使用相同的自动返航点规则。

### 9.2 飞机页签

右侧飞机控制区增加：

- `主机 1`
- `从机 2`

每个页签常驻显示在线状态；当前页签完整显示该节点的：

- 模式、解锁、电量、高度、速度、航向、位置和任务。
- 上传、验证、就绪、AUTO 和到达时间线。
- `GUIDED / LOITER / AUTO / LAND / ARM / DISARM`。
- 独立消息历史和消息原始到达时间。
- `ONLINE / OFFLINE / OPTICAL BLOCKED` 状态。

按钮必须使用当前页签确定 `target`，并在发送日志中明确显示“主机”或“从机”，避免误操作。

### 9.3 主机兼容性

主机初始选中。现有主机状态、阻塞逻辑、按钮文案、消息显示和航点发送行为保持不变。

## 10. 故障处理

- 从机 UDP 超过 3 秒无新状态：显示 `OFFLINE`，禁用从机控制。
- 小车重启：从机继续本地读飞控并重发状态，等待小车恢复。
- 从机重启：不自动执行上次未完成的云端命令；持久任务只用于校验和诊断。
- 重复命令：返回已知事务，不重复写飞控。
- MAVLink 心跳丢失：停止执行队列中的新任务并报告 `FC_OFFLINE`。
- 航点握手超时：有限重试后失败，不自动切换 `AUTO`。
- 主机或从机状态缺失：仅影响对应页签，不清空另一架飞机的状态。
- `slave_state` 超长：压缩器按优先级删除非关键字段，不得让整个 Tuya report 失败。

## 11. 测试与验收

### 11.1 自动测试

- 节点消息身份、目标、序号、校验和类型验证。
- 小车调度器主机、从机和小车路由隔离。
- 从机简单命令 ACK、去重、过期和队列满。
- 从机航点完整接收、校验、握手成功和失败回滚。
- 主机阻塞不影响从机；从机离线不影响主机。
- `rover_state` 原有 480 字节测试继续通过。
- `slave_state` 在最长模式、故障和消息文本下不超过 480 字节。
- 地面站一次状态读取解析两个属性并分别缓存。
- 页签切换后按钮和航点目标不会串台。

### 11.2 无桨联调

1. 小车和从机同时连接 `woshinailong`。
2. 验证从机 1 Hz 心跳和真实飞控模式显示。
3. 从地面站切换从机 `GUIDED/LOITER`，以飞控心跳确认。
4. 验证 `ARM/DISARM` 命令确认，保持拆桨。
5. 上传测试航点，并从飞控读取任务确认写入。
6. 同时操作一次小车或主机命令，确认从机心跳和消息不中断。
7. 断开从机网络，3 秒后地面站显示 `OFFLINE` 并禁用控制。
8. 恢复网络，确认状态自动恢复且不重放旧命令。

### 11.3 云端验收

- 一次 TuyaLink report 同时包含 `rover_state` 和 `slave_state`。
- 地面站保持一次状态轮询，不增加 OpenAPI 调用频率。
- 主机、从机和小车状态同时显示且不因部分上报消失。
- 所有从机指令从地面站经过涂鸦、小车、UDP 和从机本地飞控完整闭环。

## 12. 部署与回滚

- 先部署从机服务和小车从机链路，保持地面站从机功能隐藏。
- 完成局域网和飞控联调后，再在涂鸦增加 `slave_state`。
- 最后启用地面站从机页签。
- 每台设备部署前备份现有配置和 systemd 单元。
- 不删除或覆盖现有主机服务。
- 从机功能可通过一个配置开关整体禁用；禁用后小车和主机行为与当前版本一致。
- 实施完成后建立 Git 标签，作为国赛双机版的可恢复点。
